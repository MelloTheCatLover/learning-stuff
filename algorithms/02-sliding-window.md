# Sliding Window

Окно — отрезок подряд идущих элементов. Вместо того чтобы каждый раз пересчитывать весь отрезок, я его сдвигаю: впускаю справа, выпускаю слева, а то что внутри обновляю за O(1). Получается O(n) вместо O(n²).

От двух указателей отличается тем, что там важны два элемента на концах, а тут — все что между ними. И указатели идут в одну сторону.

## Три паттерна

Вся разница в том, как двигается левая граница.

**1. Фиксированное окно** — длина k. Левая и правая двигаются вместе, как слайдер.
Инициализация (сумма первых k), правило перехода, результат.

**2. Непересекающиеся окна (сброс)** — когда элемент ломает условие, левая граница **прыгает** за него и окно начинается заново. Например серия единиц подряд: встретил ноль — начинаю считать заново.

**3. Пересекающиеся окна (сжатие)** — расширяю направо, пока можно. Уперся в лимит — левую **двигаю по одному**, пока окно снова не станет нормальным. Например последовательность из 1 и 0, можно поменять только k нулей: уперся в лимит нулей → двигаю левую, пока не пройду ноль, тогда лимит освобождается.

Как выбрать:
- длина задана → 1
- плохой элемент портит любое окно где он есть → 2
- есть бюджет, часть окна можно спасти → 3

## Шаблоны

```ts
// 1. фиксированное
let sum = 0;
for (let i = 0; i < k; i++) sum += a[i]!;
let best = sum;
for (let r = k; r < a.length; r++) {
    sum += a[r]! - a[r - k]!;     // пришел r, ушел r - k
    best = Math.max(best, sum);
}

// 2. сброс
let cur = 0, best = 0;
for (const x of nums) {
    cur = x === 1 ? cur + 1 : 0;
    best = Math.max(best, cur);
}

// 3. сжатие — это главный
let l = 0, best = 0;
for (let r = 0; r < a.length; r++) {
    // впустить a[r]
    while (/* окно плохое */) {
        // выпустить a[l]
        l++;
    }
    best = Math.max(best, r - l + 1);
}
```

Длина окна — `r - l + 1`.

## Почему сжатие это O(n), хотя там while внутри for

Я сначала думал, что это n². Но: r проходит n шагов, l тоже максимум n, и **назад l никогда не идет**. Итого ≤ 2n. Это амортизация, как у push в Big O.

## Состояние окна

Это то, что я храню про содержимое окна, чтобы быстро проверить, нормальное оно или нет.

## Фишки

**Последний индекс (задача 3).** Храню, где символ был в последний раз. Если он внутри окна — прыгаю сразу за него, без while.

```ts
const last = new Int32Array(128).fill(-1);
let l = 0, best = 0;
for (let r = 0; r < s.length; r++) {
    const c = s.charCodeAt(r);
    if (last[c]! >= l) l = last[c]! + 1;
    last[c] = r;
    best = Math.max(best, r - l + 1);
}
```

`>= l` обязательно — символ мог быть раньше, но уже левее окна (`"abba"`, `"tmmzuxt"`), и тогда l прыгнул бы назад.
Работает только когда окно ломает повтор. Для бюджета как в 1004 не работает — непонятно куда прыгать.

**Массив вместо Map.** Если ключи — ASCII, то `Int32Array(128)` и `charCodeAt`. Только заглавные — `Int32Array(26)` и `code - 65`. Мерил на задаче 3: Set ~4 мс, Map ~1.3 мс, массив ~0.2 мс. В 20 раз, mindblowing.

**424, сколько замен.** Оставляю самую частую букву, остальное меняю. Значит нужно замен = `длина - maxCount`.

**Окно которое не сжимается.** `if` вместо `while` — окно не уменьшается, а едет. Размер окна = лучший ответ. В 424 тогда maxCount можно даже не уменьшать: окно вырастет выше рекорда только если maxCount вырос. Хитро, на собесе сначала писать обычную версию.

## Ловушки

- уходит `a[r - k]`, а не `a[l + 1]`
- при сжатии `while`, а не `if` (`"abcabcbb"`, на r = 6 выпускаю два символа)
- **отрицательные числа** ломают окно с суммой — добавил элемент, а сумма уменьшилась, непонятно что делать. Там префиксные суммы
- произведение k элементов — ноль ломает деление. Считать нули отдельно
- подмассив (подряд) → окно, подпоследовательность (не подряд) → скорее DP
- `console.log(nums.slice(l, r))` в цикле — это копия каждый раз, O(n) превращается в O(n·k). Отладку убирать

## Как узнать

- подмассив / подстрока
- самый длинный / самый короткий
- длины k
- не больше k замен / различных
- числа неотрицательные
