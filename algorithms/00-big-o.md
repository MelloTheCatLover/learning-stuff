# Big O

> Понятная вещь про скорость выполнения алгоритма и выделения памяти.

Записывается как `O(_)`. Используется для оценки эффективности алгоритма или функции, показывает рост времени выполнения (или памяти) в зависимости от **размера входных данных `n`**.

Не является прямой связью или олицетворением скорости выполнения функции. То есть не показывает время выполнения, и алгоритмы с одинаковой Big-O нотацией могут выполняться разное кол-во времени.


## Избавление от констант

Тут неважны константы помимо самого кол-ва операций, например `O(n^2 + 34n + 100)` по итогу сводится только к старшему слагаемому — `O(n^2)`. Опять же потому, что это не отражает напрямую, сколько будет выполняться та или иная функция, а олицетворяет сложность выполнения.

По определению: `O(g)` — растёт **не быстрее**, чем `c · g(n)`.


## Память

Память тоже считается:

- создал `Set` / массив на `n` элементов → `O(n)`
- рекурсия → `O(глубина)`, на стеке одновременно только одна ветка
- пара переменных-счетчиков → `O(1)`

**Время ↔ память.** Поиск дубликатов двумя циклами — `O(n^2)` по времени, `O(1)` по памяти. Через `Set` — `O(n)` по времени, но `O(n)` по памяти.

## Полиномиальное и не полиномиальное время

Разные нотации Big-O олицетворяют разную сложность. **Экспоненциальные** варианты (`2^n`, `n!`) — те, которые нельзя представить полиномом, и их решение представляет собой огромную сложность.


Например, задача коммивояжера: перебором всех путей — `n!`, как узнал можно быстрее динамикой (Хелд — Карп) — `O(n^2 · 2^n)`, но полиномиального решения никто не знает (P vs NP). Ну, по крайней мере пока очередной документ OpenAI не двинет границу, как она заявила про ETH — что 3-SAT решается субэкспоненциально.

## Самые популярные сложности

| Сложность | Название | Пример |
|---|---|---|
| `O(1)` | Константное | добавление элемента в конец массива, сложение двух чисел |
| `O(logn)` | Логарифмическое | бинарный поиск, поиск в сбалансированном BST |
| `O(n)` | Линейное | проход по массиву |
| `O(nlogn)` | — | хорошие сортировки |
| `O(n^2)` | Квадратичное | вложенный проход по массиву |
| `O(nm)` | — | проход по двойному массиву |
| `O(2^n)` | Экспоненциальное | рекурсия с двумя ветками |
| `O(n!)` | Факториальное | полный перебор перестановок |

**`O(1)`** — Константное время, происходит «мгновенно» (тут понятие не прямое — просто не зависит от `n`). Например, добавление элемента в конец массива, сложение двух чисел. В процессоре, думаю, занимает несколько ASM-операций исключительно с переназначением памяти и регистров.

**`O(logn)`** — Логарифмическая скорость. Постоянное деление на два, самое привычное — бинарный поиск по сортированному массиву. Поиск элементов в сбалансированном бинарном дереве. Для миллиона элементов — около 20 шагов.

**`O(n)`** — Линейное время. Проход по массиву. Добавление элемента в связный список — `O(1)`, если в голову или есть указатель на хвост, и `O(n)`, если надо дойти до конца. К чему стремиться — решают ограничения задачи (см. ниже), иногда можно `O(logn)` или `O(1)`.

**`O(nlogn)`** — Популярная сложность. Средний случай `qsort`, любой случай `mergesort` и `heapsort`.
- В Python и JS (V8) — **Timsort**: `mergesort` + `insertion sort` на маленьких кусках, распознает уже отсортированные куски.
- В C++ — **Introsort**: `qsort` + `heapsort`, чтобы избежать худшего случая `qsort` — `n^2`.

**`O(n^2)`** — Квадратичное время, все еще полиномиальное, ну понятно в целом. Проход по массиву вложенно, вывод элементов квадрата (двойного массива).

**`O(nm)`** — `n^2` — частный случай этого, когда `n = m`. Проход по массиву, где `n` — кол-во рядов, а `m` — кол-во элементов в ряду.

**`O(2^n)`** — Экспоненциальное время. Например, Фибоначчи, где рекурсия каждый раз порождает 2 ветки развития, каждая из которых порождает еще 2 и так далее.

**`O(n!)`** — Это просто полный перебор. Перестановки, коммивояжер перебором и тд.



## Подвохи в JS

| Операция | Сложность | Подвох | |---|---|---| | `push` / `pop` | `O(1)` | — | | `shift` / `unshift` | `O(n)` | массив сдвигается, как очередь не использовать |
| `includes` / `indexOf` | `O(n)` | внутри цикла уже `O(n^2)`, вместо этого брать `Set` |
| `Set` / `Map` | `O(1)` в среднем | внутри хеш-таблица, `Set` хранит порядок добавления |
| `sort()` | `O(nlogn)` | без компаратора сортирует как строки |
| `slice`, `[...arr]` | `O(n)` | по времени и памяти, это копия |
| `str +=` в цикле | может быть `O(n^2)` | лучше собрать массив и сделать `join` |
