# Linked List

Каждый элемент (узел) хранит значение и ссылку на следующий. В TS на LeetCode так:

```ts
class ListNode {
    val: number;
    next: ListNode | null;
    constructor(val?: number, next?: ListNode | null) {
        this.val = val ?? 0;
        this.next = next ?? null;
    }
}
```

## Чем отличается от массива

Массив лежит в памяти одним куском, поэтому `a[i]` это просто `начало + i * размер` — O(1).
Узлы списка лежат где угодно, до i-го надо пройти i ссылок — O(n).

```
массив:  [ 1 | 2 | 3 | 4 ]
список:  head → [1|•] → [2|•] → [3|•] → null
```

| | массив | список |
|---|---|---|
| a[i] | O(1) | O(n) |
| вставка в начало | O(n) | O(1) |
| вставка в конец | O(1) | O(1) только если есть ссылка на хвост |
| вставка, когда уже стою на узле | O(n) | O(1) |
| поиск | O(n) | O(n) |

Бинарного поиска в списке нет — до середины все равно идти O(n).

## Самое важное, что я понял

- `cur = ...` — меняю **переменную**, сам список не меняется
- `cur.next = ...` — меняю **узел**, вот это меняет список

Почти все мои баги были из-за этого.

## Dummy

Фейковый узел перед головой. Нужен, чтобы голова не была особым случаем (удалить голову, выбрать голову при слиянии). В конце `return dummy.next`.

И переменных две: `dummy` стоит на месте, `cur` бегает. Если одной переменной — либо теряешь начало, либо не двигаешься.

```ts
function fromArray(a: number[]): ListNode | null {
    const dummy = new ListNode();
    let cur = dummy;
    for (const v of a) {
        const node = new ListNode(v);
        cur.next = node;
        cur = node;
    }
    return dummy.next;
}
```

## Разворот (206)

**Итеративно**, три указателя. Сначала сохранить next, потому что как только разверну стрелку — остаток потеряется.

```ts
let prev: ListNode | null = null, cur = head;
while (cur) {
    const next = cur.next;   // сохранил
    cur.next = prev;         // развернул
    prev = cur;              // сдвинулся
    cur = next;
}
return prev;
```

O(n), O(1).

**Рекурсивно** — тут долго не понимал. Идея: сначала пусть рекурсия развернет хвост, а я потом прицеплю себя в конец.

```ts
if (!head || !head.next) return head;     // 0 или 1 узел — уже развернут
const newHead = reverseList(head.next);   // хвост развернут
head.next.next = head;                    // прицепил себя
head.next = null;                         // иначе цикл
return newHead;
```

Почему `head.next.next` работает: стрелку `head → второй` рекурсия не трогает. А второй после разворота хвоста стал последним. Значит `head.next` — это как раз конец, куда цепляться.

`newHead` — это последний узел исходного списка, его находит база, остальные просто передают наверх.

O(n) и память O(n) — стек. Короче работа делается на обратном пути, после рекурсии. Если менять стрелки до рекурсии — теряется хвост или получается цикл 1 ⇄ 2 (у меня так и было).

## Быстрый и медленный

slow на 1, fast на 2.

**Середина (876):**
```ts
let slow = head, fast = head;
while (fast && fast.next) { slow = slow!.next; fast = fast.next.next; }
```
`fast && fast.next` → при четной длине второй средний.
`fast.next && fast.next.next` → первый средний.

**Цикл (141), Флойд:** сначала шаг, потом сравнение. Встретились → цикл. fast уперся в null → цикла нет. Сравнивать узлы (`===`), не значения — значения могут повторяться. Через Set тоже можно, но память O(n), а так O(1).

Почему обязательно встретятся: внутри цикла fast догоняет slow на 1 узел за шаг, перепрыгнуть не может.

**n-й с конца (19):** fast уходит вперед на n+1 от dummy, потом идут вместе пока fast не null — slow стоит перед тем, кого удалять.

## Слияние (21)

```ts
const dummy = new ListNode();
let cur = dummy;
while (l1 && l2) {
    if (l1.val <= l2.val) { cur.next = l1; l1 = l1.next; }
    else { cur.next = l2; l2 = l2.next; }
    cur = cur.next;
}
cur.next = l1 ?? l2;   // остаток целиком, он уже отсортирован
return dummy.next;
```

## Палиндром (234)

Середина → развернуть вторую половину → сравнить. Собирается из 876 и 206.

## Ловушки

- проверить `fast && fast.next` прежде чем делать `fast.next.next`
- сохранить next до перепривязки
- удаление головы без dummy
- `===` по узлам, а не по val
- пустой список

## Про TS

- `!` после выражения — это я говорю компилятору «тут не null», в JS оно стирается. Это обещание, а не проверка
- из-за `noUncheckedIndexedAccess` `arr[i]` это `T | undefined`, поэтому `arr[i]!`
- `let prev = null` → TS решит что тип `null`. Надо `let prev: ListNode | null = null`

## Где я ошибался

- fromArray: `prev = a[0]` — это число, а не узел. Потом `cur = new ListNode()` без привязки. Потом `cur.val =` вместо `cur.next =`
- рекурсивный разворот: менял стрелки до рекурсии, в базе `return;` вместо `return head`
- 141: `return true` внутри цикла, условие с `||` не выходило при встрече
- 21: не двигал cur, одна переменная вместо двух, терял остаток
