## О чем задача

Дан массив. Нужно найти длину максимальной последовательности чисел, которые идут подряд (`[1, 2, 3]`) без повторов. При этом каждый элемент можно увеличить на 1, чтобы собрать последовательность лучше. Вернуть надо только число — длину.

`[1, 1, 2, 3]` не считается: две единицы — это повтор.

## Пример руками

Каждое число — фишка, которую можно положить на клетку `x` или `x + 1`. В одну клетку — не больше одной фишки.

```
вход: [2, 1, 5, 1, 1] → сортируем → [1, 1, 1, 2, 5]

шаги (dp[v] — длина полосы, которая заканчивается на v; пустое = 0):

x=1:  dp[2] = dp[1]+1 = 1    dp[1] = dp[0]+1 = 1    max=1
x=1:  dp[2] = dp[1]+1 = 2    dp[1] = dp[0]+1 = 1    max=2   ← полоса 1, 2
x=1:  dp[2] = dp[1]+1 = 2    dp[1] = dp[0]+1 = 1    max=2   ← третья единица лишняя
x=2:  dp[3] = dp[2]+1 = 3    dp[2] = dp[1]+1 = 2    max=3   ← полоса 1, 2, 3
x=5:  dp[6] = dp[5]+1 = 1    dp[5] = dp[4]+1 = 1    max=3   ← 5 слишком далеко

ответ: 3
```

## Первая мысль

Первое, что пришло в голову, — отсортировать массив. Тут если не сортировать, то идти по ветке хеш-таблицы, но с ней ничего не придумалось, поэтому сортировка пришла в голову.

Потом подумал, что нужно два указателя — быстрый и медленный, где медленный ставится в начало, а быстрый идет и сравнивает следующие элементы: можно ли из них собрать такую последовательность. Но потом понял, что идея не очень рабочая, потому что нет логики, когда двигать медленный, и нет точного понимания, что мы не пропускаем ответ, потому что мы берем каждый элемент только раз.

Еще была идея пройти двумя указателями по массивам `x` и `x + 1`. Но она считает один элемент дважды: на `[1, 2]` видно значения `1, 2, 3`, и кажется, что ответ 3, хотя элементов всего два.

Тут ничего не выгорело. Полный перебор — `2^n` вариантов (каждый элемент `x` или `x + 1`), при `n = 10^5` нереально.

Дальше я пошел в обсуждения, чтобы посмотреть, что пишут ребята. Тогда у меня появилась идея с динамическим программированием. Суть в том, что мы можем для каждого числа сохранять длину его максимальной последовательности, и для этого же числа + 1.

## Ключевая идея

Ключевая идея в том, что мы создаем хеш-таблицу (`Map`), чтобы не делать огромный массив. Ключ — само число, значение — **длина самой длинной последовательности, которая заканчивается на этом числе**. Это создает рекурсию или индукцию, по которой мы для каждого элемента вычисляем такую последовательность, следовательно, найдем и максимальную в процессе.

`dp[v]` вычисляется двумя формулами — по одной на каждый выбор элемента:

```
dp[x + 1] = dp[x] + 1      // x стал x+1, встал над полосой на x
dp[x]     = dp[x - 1] + 1  // x остался x, встал над полосой на x−1
```

Порядок именно такой: сначала `dp[x + 1]`, пока `dp[x]` еще старое, — иначе один элемент займет две клетки.

## Как решаю

1. **Подготовка:** сортирую массив, создаю `dp = new Map<number, number>()` и помощник `get`, который возвращает 0, если числа нет.
2. **Состояние:** `dp[v]` — длина самой длинной последовательности подряд, которая заканчивается на числе `v`.
3. **Переход:** для каждого `x` из отсортированного массива — две формулы: `dp[x + 1] = dp[x] + 1` и `dp[x] = dp[x - 1] + 1`.
4. **Порядок обновления и почему:**
   - элементы — по возрастанию (поэтому сортировка): к моменту обработки `x` все меньшие числа уже посчитаны;
   - внутри элемента — сначала `dp[x + 1]`, потом `dp[x]`, чтобы прочитать старое `dp[x]`.
5. **База:** числа нет в таблице → последовательности нет → 0. Отдельно ничего задавать не нужно: `+ 1` в формулах сам дает 1 для одиночного элемента.
6. **Ответ:** пока считаем последовательности для каждого элемента, считаем максимум — проверяем **и `dp[x]`, и `dp[x + 1]`**, если нашли больше, обновляем.

## Код

```ts
function maxSelectedElements(nums: number[]): number {
    const dp = new Map<number, number>();
    const get = (v: number) => dp.get(v) ?? 0;
    let result = 0;
    const sorted = Int32Array.from(nums).sort();

    for (let i = 0; i < sorted.length; i++) {
        const x = sorted[i]!;
        dp.set(x + 1, get(x) + 1);
        dp.set(x, get(x - 1) + 1);

        if (get(x) > result) { result = get(x); }
        if (get(x + 1) > result) { result = get(x + 1); }
    }

    return result;
}
```

## Сложность

- **Время:** `O(n log n)` — сортировка `O(n log n)` плюс один проход по массиву `O(n)`. 
- **Память:** `O(n)` — надо создать таблицу размером с массив, почти, там еще элемент + 1. Так что если, например, в массиве числа будут идти с пропуском одного (1, 3, 5), то таблица будет больше в два раза, но все равно `O(n)`. Плюс копия массива для сортировки — тоже `O(n)`.

## Крайние случаи

Пустой массив по условию невозможен (длина ≥ 1).

- один элемент: `[1] → 1`
- все одинаковые: `[1, 1, 1] → 2` (один остается, второй +1, третьему некуда)
- два соседних: `[1, 2] → 2`, а не 3
- большие разрывы: `[1, 4, 7, 10] → 1`
- после +1 цепочка становится длиннее исходной: `[1, 1, 2, 3] → 4` (полоса `1, 2, 3, 4`)

## Где споткнулся

Путал все, приходилось пользоваться подсказками. Также объявил метод `get`, но по итогу не использовал его.

- Вторую формулу написал `dp[x + 1] = dp[x - 2] + 1` — а полоса всегда растет на 1, под `x + 1` должна стоять `x`.
- Базу задал `dp[0] = 1` — а нуля в массиве нет, там 0.
- Использовал `dp.get` вместо `get` → `undefined + 1 = NaN`.
- Максимум проверял только по `dp[x]`, а полоса часто заканчивается на `x + 1` (как в `[1, 1, 2, 3]`).

## Как узнать такую задачу

- у каждого элемента есть **выбор** (`x` или `x + 1`), и выбор одного влияет на другие → не два указателя;
- жадно «всем +1» или «никому» не работает → не жадность;
- ответ — **цепочка значений** подряд → DP по значению, а не по индексу;
- «максимальная длина», «самая длинная последовательность» — типичные слова для DP.
