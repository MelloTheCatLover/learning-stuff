# Two Pointers

Два индекса вместо вложенного цикла. Обычно из O(n²) делает O(n), и памяти доп. почти не надо — O(1).

Разбирал по видосу еще в октябре, потом решал задачи, тут все в кучу собираю.

## Три вида

**1. С двух сторон.** Один указатель в начале, второй в конце, идут навстречу.
Нужен отсортированный массив (или какая-то симметрия, типа палиндрома).

**2. Каждому по указателю.** Две последовательности, у каждой свой указатель. Двигаем тот, у кого элемент меньше. Это по сути merge из merge sort.

**3. Быстрый и медленный.** Оба с начала. Быстрый читает все подряд, медленный — это место, куда писать следующий «нормальный» элемент.

## Почему с двух сторон вообще работает

Вот тут надо понять, а не запомнить.

Массив отсортирован → если двигаю левый вправо, сумма только растет, если правый влево — только падает. То есть на каждом шаге есть ровно одно правильное направление.

Почему ничего не теряем (167): если `a[l] + a[r] < target`, то `a[l]` с любым другим правым даст еще меньше, потому что все они ≤ `a[r]`. Значит `a[l]` точно не в ответе — выкидываем, `l++`.

Почему не из середины — потому что оттуда каждый указатель мог бы пойти в обе стороны, и нет правила куда.

```ts
let l = 0, r = a.length - 1;
while (l < r) {              // именно <, нужны два разных элемента
    const s = a[l]! + a[r]!;
    if (s < target) l++;
    else if (s > target) r--;
    else return [l + 1, r + 1];   // в 167 индексы с 1
}
```

## Быстрый и медленный — Move Zeroes (283)

Тут я реально путался. Медленный двигается, когда быстрый нашел **НЕ ноль**, а не ноль. Ненулевой едет на место slow, нули сами уходят в хвост.

```ts
let slow = 0;
for (let fast = 0; fast < nums.length; fast++) {
    if (nums[fast] !== 0) {
        [nums[slow], nums[fast]] = [nums[fast]!, nums[slow]!];
        slow++;
    }
}
```

Инвариант: все левее slow — ненулевые в исходном порядке, между slow и fast — нули.

Пока в начале идут не нули, slow === fast и обмен сам с собой ничего не ломает, поэтому отдельно искать первый ноль не надо (я сначала так и сделал, работало, но длиннее).

## Задачи, коротко идея

- **167 Two Sum II** — с краев, меньше → l++, больше → r--
- **1 Two Sum** — массив НЕ отсортирован, поэтому Map, а не указатели. Если отсортировать — потеряешь индексы
- **15 3Sum** — сортирую, фиксирую i, на остатке делаю 167. O(n²). Дубликаты пропускать, иначе одинаковые тройки
- **16 3Sum Closest** — то же, только храню ближайшую сумму. Решил ее раньше 15 :)
- **26** — slow это длина уникальной части
- **80** — писать, если `a[fast] !== a[slow - 2]` (каждое число максимум 2 раза)
- **88 Merge Sorted Array** — заполнять с конца, там свободное место. И не забыть хвост nums2
- **11 Container** — двигать меньшую стенку, большая все равно не поможет
- **2567** — low score всегда можно сделать 0. Изменить элемент = выкинуть его. А выкидывать выгодно только с краев. Итого 3 варианта, берем минимум:
  `min(a[n-1] - a[2], a[n-3] - a[0], a[n-2] - a[1])`.
  За O(n) — просто найти 3 минимума и 3 максимума за проход.

Про 16 и отсечения: если минимальная сумма для i уже ≥ target — дальше только больше, break. Если максимальная ≤ target — для этого i лучше не будет, continue. Это все из-за монотонности (отсортировано).

## Как узнать задачу

- отсортированный массив
- найти пару / тройку с суммой
- сделать на месте за O(1) памяти
- слить две последовательности
- палиндром

## Ловушки

- `<` или `<=` в while
- перевернутое условие в fast/slow — проверять на `[2, 1]`, `[0]`
- `sort()` портит входной массив — на собесе сказать вслух
- память ответа обычно не считают, говорить «O(1) доп. памяти, не считая ответа»
